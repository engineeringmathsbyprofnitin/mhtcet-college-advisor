# Stage 11d - vacancy shown on the page, in the PDF and in the explanation

- Packaging (`ingestion/package_real.py`, `add_vacancy`): tables/vacancy.csv becomes one `vacancies` row per website course (`seat_type_code` = ALL, `vacancy_count` = the printed "Vacant CAP Seats") plus one `source_documents` row (type vacancy_position, official URL, file name, sha256). Courses not on the website (a new course without cutoff history) are counted, not packaged. Mixed years or rounds, or a source missing from the archive manifest, stop the packaging. The data version now also covers the vacancy, so it changes when the vacancy changes. The existing validator still runs (Round III/IV only, source must be a vacancy_position document).
- Wording (page table, mobile cards, PDF, explanation, data note): "Seats open going into Round IV" (or III when only Round III exists). The figure is the TOTAL for the course as printed by CET Cell; it includes All India and Minority seats where printed and is not specific to the student's category. It does not guarantee admission. Without vacancy data the old text "Vacancy data unavailable" stays. A printed 0 is shown as 0.
- The three identical engine copies (frontend/engine.js, recommendation/engine.js, backend/apps-script/Engine.gs) carry the same explanation text.
- Tests: tests/test_stage11d.py (10), tests/real_vacancy.test.js (2: every shown figure equals the table, Round IV only, wording), tests/real_data.test.js and tests/ui_stage6.test.js updated for the new wording.
- Not done: a figure per student category/seat type (later improvement); fees, accreditation, placements (Stage 12).
