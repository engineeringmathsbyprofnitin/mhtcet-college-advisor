# Stage 12a-3 - FRA fees linked to colleges and shown on the page

- `ingestion/build_fees.py`: links `data/normalized/fees/fra_fees_<year>_engg.csv` to the website colleges and writes `tables/fees.csv` + `fees_build_report.json`. A fee is published only if the FRA code EN#### equals the CET college code AND the names are similar (fuzzy check), or the owner confirmed the pair in `data/manual/fee_name_confirmations.csv` (columns inst_id, cet_institute_code, confirmed_note; starts empty). Never published: non-EN codes (6), colleges not on the website (2), code match with a different-looking name until confirmed (8), "Interim Order of High Court" (2, fee not final), a printed 0 or a total that contradicts tuition + development for the tuition row (the printed total is kept; EN3194), blanks (never zero).
- Real data (2026-27): 301 colleges get a fee (601 rows: tuition + total, EN3194 total only).
- Packaging (`ingestion/package_real.py`, `add_fees`): rows into the website `fees` table (fee_type tuition/total, scope "FRA approved, all engineering branches of the institute, first year") + one source document (type fee_notice, the FRA page, SHA-256 of the saved answer). The publish workflow runs `build_fees` and also starts after "Read the approved fees".
- Wording: the "total" fee is the FRA tuition + development fee; the page, the budget choice in the form, and the explanation now say so and that hostel, transport and exam charges are NOT included (the old wording "Total yearly expenses ... hostel, transport, exams" was wrong for this data). Three engine copies kept identical.
- Tests: `tests/test_stage12a3.py` (18) and `tests/real_fees.test.js` (4: every shown fee equals the table for both fee bases, explanation wording, budget filter). Older tests adapted (fee may now be a number).
- Not done: category-wise fees, hostel/other charges, Interim-Order colleges, the 8 unconfirmed names, earlier years' fees, a "fee status" note on cards.
